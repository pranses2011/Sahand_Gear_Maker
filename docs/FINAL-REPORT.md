# گزارش نهایی تحویل — Sahand Gear Designer نسخهٔ 0.1.0

این گزارش طبق قالب «بخش ۷ — قالب گزارش نهایی» سند [۰۶-آزمون](../prompts/sahand-gear-designer/06-testing-and-roadmap.md) نوشته شده و **فقط چیزهایی را می‌گوید که واقعاً انجام شده‌اند**.

## ۱) چه ساخته شد؟

### هستهٔ هندسی (build و test واقعی روی لینوکس — ۵۸/۵۸ آزمون سبز)

- **موتور اینولوت** (`SahandGearMaker.Geometry`): پروفیل چرخ‌دندهٔ خارجی/داخلی با نمونه‌برداری مبتنی بر «خطای وتر» (نه تعداد نقطهٔ ثابت)، فیلهٔ ریشهٔ سقف‌گذاری‌شده، پهلوهای کامل و قوس سر/ریشه.
- **پنج خانوادهٔ هندسی با مش آب‌بند (watertight)** — تأییدشده با آزمون «هر یال دقیقاً دو بار»:
  - خارجی مستقیم (پیاده‌سازی‌شده)
  - خارجی مارپیچ، جناغی، داخلی، شانه (محدود/آزمایشی — محدودیت‌ها در ماتریس قابلیت)
- **ویژگی‌های بدنه**: بور، شیار خار، توپی، سوراخ‌های سبک‌سازی (فقط بدون بور — محدودیت مستند).
- **مدل داده و اعتبارسنجی** (`Domain`): پارامترها با کدهای پیام پایدار، پیام‌های فارسی «چه/چرا/چه‌کار»، تفکیک خطا/هشدار/اطلاع/بررسی‌نشده، کاتالوگ قابلیت واقعی که انواع راه‌راه را رد می‌کند.
- **مونتاژ** (`Assembly`): فاصلهٔ محور و نسبت جفت خارجی/داخلی/شانه-پینیون با بررسی سازگاری؛ قطار مرکب با نسبت/جهت؛ مجموعهٔ سیاره‌ای با قید `zᵣ=zₛ+2zₚ`، نسبت‌های ویلیس و قید تقسیم‌پذیری فاز.
- **ماندگاری** (`Persistence`): فایل بومی `.sgdproj` با **ذخیرهٔ اتمی** (tmp→جایگزینی)، مهاجرت نسخه و **حفظ دادهٔ ناشناخته**؛ آزمون round-trip کامل سبز.
- **خروجی‌ها** (`Exports`): STL باینری/متنی، OBJ+MTL، PLY باینری، GLB — همه با **اعتبارسنجی پس از نوشتن** (خواندن مجدد فایل)، پریست‌های کیفیت مقیاس‌پذیر و تبدیل واحد صریح.

### رابط کاربری ویندوزی (WPF/MVVM — کد کامل، ساخت فقط روی ویندوز)

- پوستهٔ فارسی **راست‌به‌چپ** با فونت **وزیرمتن همراه** (منبع محلی، بدون نصب) و پالت رنگ سند ۰۲.
- صفحهٔ **خانه** (شروع سریع + وضعیت صادقانهٔ قابلیت‌ها)، **طراح** (فرم پارامتر + بوم سه‌بعدی تعاملی + درخت پروژه + پیام‌ها)، **خروجی** (ویزارذ ۴ گامی)، **بازخورد** (فرم درون‌برنامه‌ای + صف محلی + پاک‌سازی)، **درباره** (اطلاعات سازنده از منبع واحد).
- **رندرر سه‌بعدی نرم‌افزاری** (Z-Buffer روی WriteableBitmap) با چرخش/Pan/Zoom، نماهای استاندارد، سه حالت نمایش — بدون هیچ وابستگی native.

### زیرساخت

- CI گیت‌هاب: ساخت هسته + اجرای آزمون‌ها روی ubuntu-latest (`.github/workflows/core.yml`).
- چهار پروژهٔ نمونهٔ بی‌خطر `.sgdproj` در `samples/`.
- مستندات: معماری، ماتریس قابلیت، راهنمای ساخت، راهنمای کاربر، حریم خصوصی، اعلامیه‌های شخص ثالث.

## ۲) چه چیزی پشتیبانی نمی‌شود یا آزمایشی است؟

| مورد | وضعیت صادقانه |
|---|---|

| سینماتیک/انیمیشن، اندازه‌گیری/مقطع، نقشهٔ ۲بعدی | نقشهٔ راه |
| تحلیل استحکام/عمر/صدا | خارج از دامنه — ادعا نمی‌شود |
| ارسال واقعی بازخورد | سرویس سمت‌سرور پیکربندی نشده؛ دکمه/وضعیت صادقانه اعلام می‌کند و پیام محلی صف می‌شود |
| بررسی تماس/تداخل دقیق | اسمی/تقریبی؛ همیشه با برچسب «بررسی‌نشده» تفکیک شده |

## ۳) چطور اجرا/ساخته/آزمون می‌شود؟

```bash
# ساخت هسته (هر OS)
dotnet build src/SahandGearMaker.Geometry -c Release

# اجرای آزمون‌ها (۵۸ آزمون — نتیجهٔ واقعی آخرین اجرا: ۵۸ گذر، 0 شکست)
dotnet test tests/SahandGearMaker.Tests -c Release

# ساخت و انتشار برنامهٔ ویندوزی (روی ویندوز)
dotnet publish src/SahandGearMaker.App -c Release -r win-x64 --self-contained true -o publish/win-x64
```

CI نیز همین را روی ubuntu-latest اجرا می‌کند: ساخت شش کتابخانهٔ هسته + آزمون کامل.

## ۴) فایل نهایی کجاست؟

- کد منبع: `src/` (۷ پروژه) + `tests/` + `samples/` + `docs/` در همین مخزن.
- **بستهٔ ویندوزی قابل اجرا تولید نشده است** — زیرا محیط اجرای این تحویل لینوکسی است و WPF فقط روی ویندوز ساخته می‌شود؛ فرمان دقیق publish در بالا آمده است. بسته‌بندی installer (MSIX/InnoSetup) در گام بعدی انتشار است.

## ۵) وضعیت آفلاین/گزارش

- هستهٔ برنامه **هیچ درخواست شبکه‌ای ندارد** (تأیید با بازبینی کد: هیچ HttpClient/SMTP در مسیر اصلی وجود ندارد).
- ارسال بازخورد: interface و قرارداد JSON پیاده شده؛ endpoint پیکربندی نشده → ارسال غیرفعال و صادقانه اعلام می‌شود؛ صف محلی در `%LocalAppData%\SahandGearMaker.Designer` نگه داشته می‌شود.
- اطلاعات سازنده (نام/تلفن/ایمیل/وب) از منبع واحد `AppInfo` می‌آید؛ **هیچ شمارهٔ کارت بانکی در مخزن وجود ندارد** (بازرسی شد).

## ۶) محدودیت‌ها و گام‌های بعدی پیشنهادی

1. **تأیید عینی UI روی ویندوز**: کد WPF کامل است اما در این محیط ساخته/اجرا نشده؛ اولین گام بعدی، ساخت روی ویندوز و رفع ایرادهای احتمالی XAML/دسترس‌پذیری است.
2. مونتاژ سیاره‌ای/قطار در UI با استفاده از محاسبات آمادهٔ `Assembly`.
3. سوراخ‌های سبک‌سازی با بور (توپولوژی چندمؤلفه‌ای + مش سوراخ‌دار).
4. خروجی 3MF (نیازمند ساخت ZIP معتبر) و نقشهٔ ۲بعدی DXF/SVG.
5. دستیار انتخاب اندازه (بستهٔ A سند ۰۷) روی هستهٔ موجود.
6. سرویس سمت‌سرور بازخورد + فعال‌سازی ارسال HTTPS واقعی.
